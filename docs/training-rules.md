# Правила тренировок и API

Обзор 12 возможностей и форматы обоих CSV находятся в [README](../README.md). Все перечисленные маршруты требуют `X-Api-Key` и `X-Telegram-User-Id`. ID сессии, упражнения, шаблона и записи расписания проверяются на принадлежность пользователю.

## Подходы и жизненный цикл

- `PUT /api/training/sessions/{id}/sets/{setId}` заменяет показатели конкретного неотменённого подхода. Активные и завершённые тренировки поддерживаются; отменённые — нет. Тело содержит `sessionExerciseId`, `weight`, `repetitions`, `durationSeconds`, `distance`, `rpe`, `notes`, `warmup`. Неуказанные необязательные показатели очищаются. `warmup` по умолчанию `false`.
- `DELETE /api/sessions/{id}/sets/{setId}` логически удаляет подход. Если удалён последний подход завершённой тренировки, она получает статус `CANCELLED`. Исправление и удаление в истории полностью пересчитывают силовые рекорды пользователя по рабочим подходам оставшихся завершённых тренировок.
- `POST /api/sessions/{id}/finish` требует хотя бы один подход. Тренировка, открытая 12 часов и более, требует явного времени через `POST /api/training/sessions/{id}/finish-at`, тело `{"finishedAt":"2026-09-24T18:30:00Z"}`. Оно должно быть между началом и текущим временем, не раньше последнего подхода. В Telegram время вводится в местном формате `2026-09-24 21:30`.
- `POST /api/training/sessions/{id}/pause`, тело `{"paused":true}` или `{"paused":false}`. Повторение того же значения не удваивает паузу. В паузе нельзя добавлять подходы и запускать отдых. Пауза очищает текущий таймер отдыха.
- `POST /api/training/sessions/{id}/rest`, тело `{"seconds":90,"extend":false}`. `seconds=0` отключает таймер; `extend=true` продлевает ещё действующий таймер, иначе отсчёт идёт от текущего момента. Один запрос задаёт 0–3600 секунд. Пауза исключается из длительности тренировки; отдых включается.

Пример исправления силового подхода:

```json
{"sessionExerciseId":123,"weight":70,"repetitions":8,"rpe":8,"notes":"Исправлен вес","warmup":false}
```

## Состав активной тренировки

`POST /api/training/sessions/{id}/exercises` принимает:

```json
{"itemId":123,"exerciseId":7,"position":1,"skipped":false}
```

- `itemId` — ID упражнения внутри сессии. Если отсутствует, добавляется новое упражнение; тогда обязателен `exerciseId` из каталога.
- `exerciseId` при существующем `itemId` заменяет упражнение, только если у него нет действующих подходов. Старые цели и индивидуальный план очищаются.
- `position` — новая позиция от 0 до количества упражнений минус один. Перестановка проверяется транзакционно; ограничения БД не мешают обмену позициями.
- `skipped` помечает пропуск, не удаляя уже записанные подходы. Новый подход снимает пропуск.
- Число упражнений ограничено 30. Шаблон не изменяется. `POST /api/training/sessions/{id}/template?name=...` создаёт отдельный шаблон из непропущенных упражнений с их целями; фактические подходы не превращаются автоматически в план.
- `GET /api/training/sessions/{id}/comparison` возвращает число запланированных/выполненных рабочих подходов, превышение плана, пропуски и текущий/предыдущий силовой объём. Предыдущее выполнение ищется среди последних 100 завершённых сессий с этим упражнением, раньше текущей. Если цель не задана, превышение не вычисляется. В боте дополнительно показаны цели и фактические метрики соответствующего типа.

## Цели и отдельные подходы

Элемент `exercises` в теле создания/изменения шаблона поддерживает `durationSeconds`, `distance`, `plan`. В ответах цели называются `targetDuration`, `targetDistance`. Пример:

```json
{"exerciseId":7,"sets":2,"reps":8,"weight":70,"restSeconds":90,"plan":[{"reps":10,"weight":20,"warmup":true},{"reps":8,"weight":70,"warmup":false},{"reps":8,"weight":70,"warmup":false}]}
```

При непустом `plan` именно его рабочие элементы определяют число запланированных рабочих подходов. Метрики валидируются по типу упражнения. Цели не являются фактически выполненными результатами; каждое выполнение подтверждает пользователь. В боте быстрый выбор веса и повторов берёт следующий элемент плана; для кардио и времени цель показана на экране, фактические значения вводятся вручную.

## Импорт и история

- `POST /api/workouts/import`, multipart-поле `file`: проверяет и сразу сохраняет шаблон. `replaceId` заменяет принадлежащий пользователю шаблон, `allowDuplicate=true` разрешает создание копии уже импортированного плана. Без такого выбора повтор возвращает 409. Предпросмотр в Telegram ничего не создаёт; сохранение создаёт недостающие личные упражнения и шаблон в одной транзакции.
- `POST /api/training/history` добавляет прошедшую тренировку. Нужен `Idempotency-Key` длиной 1–92 символа; повтор возвращает 409. Тело: `name`, `startedAt`, `finishedAt`, `pausedSeconds` (по умолчанию 0), `exercises`. Каждый элемент `exercises` содержит `exerciseId` каталога и массив `sets` с обычными показателями подхода; `sessionExerciseId` в этих вложенных подходах не используется.
- `POST /api/training/history/import`, multipart-поле `file`: атомарно импортирует отдельный CSV истории. Повтор идентичного файла возвращает 409. В Telegram сначала показывается предпросмотр и требуется сохранение.
- `GET /api/training/history/export?month=2026-01`: отдаёт `text/csv` с действующими подходами завершённых тренировок указанного местного месяца. Длительность пауз сохраняется. Импортированный файл создаёт новые сессии и не меняет исходные ID.
- Прошедшее занятие не занимает слот активной тренировки. Будущее окончание, неверные показатели или более 100 подходов на упражнение отклоняются. Все строки файла проверяются до записи; ошибка при сохранении также откатывает весь импорт.

Пример ручной истории:

```json
{"name":"Грудь","startedAt":"2026-01-10T15:00:00Z","finishedAt":"2026-01-10T16:00:00Z","pausedSeconds":120,"exercises":[{"exerciseId":7,"sets":[{"weight":70,"repetitions":8,"warmup":false}]}]}
```

## Недельная цель, расписание и напоминания

`GET / PUT /api/training/settings` читает или сохраняет настройки:

```json
{"weeklyGoal":3,"restNotifications":false,"weightStep":2.5,"repMin":8,"repMax":12}
```

Цель — 1–14 завершённых тренировок за местную неделю с понедельника. Шаг веса — 0.125–100 кг, до трёх десятичных знаков. Границы повторений — от 1 до 100, верхняя не меньше нижней. `GET /api/training/goal` возвращает цель, выполненное количество и ближайшее занятие.

`GET /api/training/schedule` возвращает ближайшие и повторяющиеся события (до 50). `POST /api/training/schedule` создаёт событие или изменяет его при наличии `id`:

```json
{"templateId":12,"localStart":"2026-10-01T18:00:00","repeatWeeks":2,"reminders":false}
```

`localStart` — местное время **без смещения**, интерпретируемое в часовом поясе профиля. Невозможное время при переходе на летнее время отклоняется; при двукратном времени используется первое допустимое смещение. `repeatWeeks=0` — однократно, 1–4 — повтор через указанное число недель. Для переноса передайте `id` и новое время. `DELETE /api/training/schedule/{id}` отменяет событие вместе с будущими повторениями. Удалённые шаблоны не порождают напоминаний. Смена часового пояса сохраняет местное время расписания.

Напоминание приходит в момент запланированного начала; оно не запускает и не завершает тренировку автоматически. После обработки очередного повторения следующее время сдвигается на заданное число недель; так поддерживаются недельные и двухнедельные циклы с отдельными событиями для A/B.

Таймеры и расписание находятся в PostgreSQL. Фоновый обработчик проверяет их примерно каждые 5 секунд при включённом Telegram. Напоминания отдыха и расписания по умолчанию выключены. После простоя сообщения отдыха старше 2 минут и занятия старше суток пропускаются; повторяющееся событие переносится к следующему будущему вхождению. Telegram 429 откладывает повтор, блокировка бота (403) не зацикливает доставку. Если процесс завершится после отправки уведомления, но до фиксации транзакции, при восстановлении возможен повтор сообщения.

## Аналитика и следующий план

`GET /api/analytics/{period}` поддерживает `workingOnly` и `equalElapsed`, оба по умолчанию `true`. `GET /api/exercises/{id}/progress` поддерживает `period`, `workingOnly=true`, `bySession=true`; `bySession=false` возвращает месячные максимумы. Поле точки `month` сохранено для совместимости: при `bySession=true` оно содержит местные дату и время тренировки, при `false` — месяц. Две тренировки в одну минуту остаются разными точками. Рекорды всегда рассчитываются только по рабочим силовым подходам.

`GET /api/training/suggestions/{templateId}` возвращает предложенный шаблон и объяснение. Правило использует последнее завершённое выполнение упражнения, исключая разминку. Нужны силовой тип, заданные вес и число подходов, достаточное количество рабочих подходов; каждый должен достигнуть верхней границы повторов и не меньшего веса. Тогда к весу прибавляется настроенный шаг, а повторы устанавливаются на нижнюю границу. Вес выше 2000 кг не предлагается. Индивидуальные планы подходов остаются без изменений. Ни получение предложения, ни его просмотр не меняют шаблон: в API применяется обычный `PUT /api/workouts/{id}`, в боте — отдельная кнопка подтверждения.
