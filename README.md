# Дневник тренировок в Telegram

**Планируйте → тренируйтесь → записывайте → анализируйте → повторяйте.**

Бот для ведения тренировок: Java 17, Spring Boot 3.5, Spring Data JPA, PostgreSQL 17, Flyway, Maven и Docker Compose. Основной интерфейс — личный чат в Telegram. Команды (например, `/start` и `/menu`) открывают новое сообщение внизу чата. Нажатия кнопок обновляют текущий экран; подтверждённые подходы сразу сохраняются в базе. Старые кнопки после открытия нового экрана не изменяют данные.

## Запуск через Docker

Потребуются Docker Engine / Docker Desktop с Compose и токен Telegram-бота. Локальные Java и Maven для этого способа не нужны.

1. Создайте бота через [@BotFather](https://t.me/BotFather): команда `/newbot`, название и имя пользователя.
2. Если `.env` ещё нет, скопируйте пример:

   ```powershell
   Copy-Item .env.example .env
   ```

   В Linux/macOS: `cp .env.example .env`.
3. Редактируйте именно **`.env`**, а не `.env.example`: Docker Compose читает `.env`. Укажите разные случайные значения `POSTGRES_PASSWORD` и `INTERNAL_API_KEY`, свой `TELEGRAM_BOT_TOKEN` и `TELEGRAM_ENABLED=true`. `.env` исключён из Git и контекста сборки Docker.
4. Запустите приложение:

   ```sh
   docker compose up --build -d
   docker compose logs -f app
   ```

5. Откройте личный чат с ботом, отправьте `/start`, при необходимости выберите **Русский / English**, затем **Начать / Start**.

После изменения переменных `.env` выполните `docker compose up -d app`: простой `restart` не обновляет окружение контейнера. После изменения кода используйте `docker compose up --build -d app`.

HTTP-сервис слушает `http://localhost:8080`, но отдельной главной веб-страницы нет. Проверка состояния: [health](http://localhost:8080/actuator/health), документация API: [Swagger UI](http://localhost:8080/swagger-ui/index.html). HTTP доступен только через loopback; PostgreSQL наружу не опубликован.

При `TELEGRAM_ENABLED=false` API продолжает работать без токена. Включённый Telegram с пустым токеном не даст приложению запуститься. Если `.env` был создан автоматически, Telegram в нём может быть выключен.

```sh
docker compose ps
curl http://localhost:8080/actuator/health
docker compose restart app       # Проверить восстановление после перезапуска
docker compose stop              # Остановить, сохранив контейнеры и базу
docker compose down              # Удалить контейнеры, сохранив том базы
```

Не удаляйте том `postgres_data`, если нужна история тренировок. Перед миграциями и обслуживанием делайте резервную копию PostgreSQL. Пример для оболочки Linux/macOS:

```sh
docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB"' > workout.sql
```

Храните копии вне репозитория и отдельно проверяйте восстановление.

Если после перезапуска кажется, что бот молчит, отправьте `/start` или `/menu`: появится новый экран внизу чата. Сам запуск контейнера не отправляет приветствия; ранее включённые напоминания могут сработать после восстановления. В старых версиях команды редактировали самое первое сообщение бота, поэтому ответ можно было не заметить выше в переписке.

## Язык и настройки

Доступны **русский (`ru`)** и **английский (`en`)**. Выбор — на приветственном экране или в **Настройки → Русский / English**. Язык хранится отдельно для каждого пользователя в PostgreSQL, применяется сразу и сохраняется после перезапуска. По умолчанию используется английский.

Переводятся меню, кнопки, подсказки, единицы измерения и сообщения об ошибках. Пользовательские названия тренировок, упражнений и заметки сохраняются как введены. Названия исходного каталога также остаются на английском: например, `Bench Press`. Можно создавать свои упражнения с русскими названиями, в том числе через CSV. Список команд Telegram имеет русские описания для русского языка самого Telegram; язык экранов выбирается отдельно в боте.

В настройках также задаётся часовой пояс IANA, например `Europe/Moscow`. По умолчанию — `UTC`. Неделя начинается в понедельник; даты тренировок и границы отчётов рассчитываются в выбранном часовом поясе. Единицы — кг и км.

## Работа с ботом

| Команда | Назначение |
| --- | --- |
| `/start` | Приветствие, главное меню или восстановление текущей тренировки |
| `/menu` | Главное меню |
| `/workout` | Выбор, создание или импорт шаблона |
| `/history` | История завершённых тренировок |
| `/progress` | Отчёты и прогресс упражнений |
| `/cancel` | Отмена текущего ввода; сама тренировка не отменяется |

Создание вручную: **Тренировки → Создать тренировку → название → Добавить упражнение → Сохранить тренировку**. Доступны каталог, поиск и создание собственного упражнения. У шаблона можно менять название, описание, порядок и состав упражнений, а также плановые значения. Изменение шаблона не переписывает историю.

Плановые значения зависят от типа: силовые/свой вес — `подходы повторы вес отдых_сек`; на время — `подходы длительность_сек отдых_сек`; кардио — `подходы длительность_сек дистанция_км отдых_сек`. Например: `4 8 70 90`, `3 45 60` и `2 600 2 90`. Для пропуска значения используйте `-`. Кнопка **План по подходам** задаёт разные значения для каждого подхода, включая разминку (`w`) и рабочие подходы (`r`). Черновик хранится в базе до сохранения. `/cancel` сбрасывает текущий ввод и черновик, сохраняя уже созданные шаблоны и записанные подходы.

Во время тренировки:

- **Добавить подход → вес → повторы** сразу сохраняет подход. Предлагаемые значения берутся из текущих/предыдущих подходов или плана.
- **Повторить [подход]** записывает ещё один такой подход; RPE и заметки не копируются.
- **Убрать последний подход** отменяет конкретный подход. Повторное нажатие устаревшей кнопки не удаляет следующие подходы.
- Переключение упражнений сохраняет все подтверждённые подходы.
- Завершение и отмена требуют подтверждения. Отменённая тренировка остаётся в базе, но не входит в историю завершённых тренировок и аналитику.
- `/start` предлагает продолжить, завершить или отменить активную тренировку, в том числе после перезапуска.

Ручной ввод показателей:

| Тип упражнения | Формат | Пример |
| --- | --- | --- |
| Силовое | `вес_кг повторы` | `70 8` |
| Собственный вес | `повторы [дополнительный_вес_кг]` | `12` или `12 5` |
| Кардио | `длительность_сек расстояние_км` | `1800 5` |
| На время | `длительность_сек` | `60` |

Можно добавить `| RPE | заметку`, например `70 8 | 8.5 | Хорошая техника`. Для пропуска RPE используйте `-`. Сообщение сразу сохраняет подход. Вес и расстояние допускают до трёх знаков после запятой, RPE — один. Ограничения проверяются приложением и базой.

## Импорт тренировки из CSV

CSV импортирует **шаблон будущей тренировки** с плановыми значениями. Для фактически выполненных подходов используйте обычную тренировку или отдельный импорт истории, описанный ниже. Один файл содержит одну тренировку и от 1 до 30 упражнений; порядок строк задаёт порядок упражнений.

В Telegram откройте **Тренировки → Импорт CSV** и отправьте файл **как документ**. Предпросмотр проверяет весь файл и не создаёт ни шаблонов, ни упражнений. Затем выберите **Создать новый шаблон** или **Заменить существующий шаблон** (с отдельным подтверждением замены). Повторный файл помечается предупреждением. `/cancel` отменяет ввод. История и активная тренировка при замене шаблона сохраняются.

Готовые примеры: [обычный план](docs/workout-example.csv), [разные подходы и разминка](docs/workout-per-set-example.csv). Старый формат из семи столбцов продолжает поддерживаться; расширенный содержит десять:

```csv
workout,exercise,metric_type,sets,reps,weight,rest_seconds,duration_seconds,distance,set_plan
Грудь и плечи,Bench Press,STRENGTH,3,8,70,90,,,
Грудь и плечи,Shoulder Press,STRENGTH,3,10,20,60,,,
Грудь и плечи,Планка,TIMED,3,,,60,45,,
Грудь и плечи,Running,CARDIO,1,,,90,600,2,
```

| Столбец | Содержимое |
| --- | --- |
| `workout` | Название тренировки, 1–80 символов; одинаковое во всех строках |
| `exercise` | Название упражнения, 1–80 символов |
| `metric_type` | `STRENGTH`, `BODYWEIGHT`, `CARDIO` или `TIMED`; регистр не важен |
| `sets` | Плановое число подходов, 1–100; необязательно |
| `reps` | Плановое число повторов, 0–1000; необязательно |
| `weight` | Плановый вес в кг, 0–2000, до трёх десятичных знаков; необязательно |
| `rest_seconds` | Отдых в секундах, 0–3600; в боте запускает таймер после записи подхода |
| `duration_seconds` | Целевая длительность подхода, 1–604800 секунд; для `TIMED` и `CARDIO` |
| `distance` | Целевая дистанция, 0–10000 км, до трёх десятичных знаков; только `CARDIO` |
| `set_plan` | JSON-массив индивидуальных подходов, до 100; пусто или `[]` означает общий план |

Правила файла:

- Кодировка **UTF-8**, допускается BOM; размер до **64 КиБ** (65 536 байт).
- Первая строка — заголовки выше, в указанном порядке. Названия столбцов остаются английскими при любом языке интерфейса.
- Разделитель — запятая или точка с запятой, одинаковый для всего файла. При экспорте из Excel выбирайте CSV UTF-8.
- Необязательные значения — пустая ячейка или `-`. Числа без разделителей тысяч; десятичная точка рекомендуется. Десятичная запятая допустима при разделителе `;` либо внутри кавычек.
- Поля с разделителем или переводом строки заключаются в двойные кавычки. Кавычка внутри поля удваивается: `"Жим ""сидя"""`.
- Пустые строки пропускаются; начальные и конечные пробелы значений удаляются.
- Упражнение ищется по точному названию без учёта регистра среди личных и общих упражнений. Личное имеет приоритет. Затем проверяются русские псевдонимы: жим лёжа/лежа, жим над головой, приседания, бег, отжимания. Они соответствуют английским упражнениям каталога. Если совпадений нет, при подтверждении создаётся личное упражнение указанного типа. Другие пользователи его не видят.
- Тип должен совпадать с типом найденного упражнения. Ошибка отменяет весь импорт; корректные строки отдельно не сохраняются. Ошибки содержимого строки показывают её номер в последовательности CSV-записей, включая заголовок; пустые строки не считаются.
- Новые упражнения и шаблон создаются одной транзакцией только после подтверждения. При ошибке всё откатывается. Отпечаток разобранного файла позволяет обнаруживать повторный импорт; явно разрешённая копия создаёт отдельный шаблон.


## Новые правила тренировок

Все 12 улучшений доступны в боте и внутреннем API. Подробные правила, ограничения и маршруты: [docs/training-rules.md](docs/training-rules.md).

1. **Исправление подходов:** кнопка «Исправить подходы» в активной тренировке и подробностях истории. Можно изменить метрики, RPE, заметку и признак разминки или удалить подход. Рекорды пересчитываются. Удаление последнего подхода завершённой тренировки отменяет её, чтобы пустая запись не увеличивала статистику.
2. **Корректное завершение:** пустую тренировку можно только отменить. После 12 часов бот просит фактическое время окончания, не раньше последнего записанного подхода.
3. **Изменение на ходу:** добавить, заменить, пропустить или переставить упражнение можно в «Изменить упражнение». Замена недоступна, если уже записаны подходы. Шаблон меняется только через явное создание нового шаблона.
4. **Цели для кардио и времени:** длительность и дистанция хранятся в шаблоне и снимке тренировки, доступны в CSV.
5. **План по подходам:** разные веса/повторы/время и разминка. Например, две строки `w 20 10` и `r 70 8`. При быстром вводе предлагаются параметры следующего запланированного подхода.
6. **План и факт:** рабочие подходы, превышение плана, пропуски, плановые метрики, фактическое время/дистанция/повторы и сравнение силового объёма с предыдущим выполнением упражнения.
7. **Отдых и пауза:** таймер после подхода, «+30 сек», пропуск отдыха, пауза/продолжение. Состояние хранится в БД. Уведомления отдыха включаются в настройках тренировок и по умолчанию выключены.
8. **Безопасный импорт шаблонов:** предпросмотр без записей в БД, русские псевдонимы, обнаружение повторов, создание копии или подтверждённая замена.
9. **Прошлые тренировки:** «История → Прошедшая тренировка» запрашивает дату, время и фактические подходы по упражнениям шаблона. «Импорт истории» и «Экспорт CSV» используют отдельный формат ниже.
10. **Цели и расписание:** «План тренировок и цели», цель 1–14 занятий в неделю, одноразовые и повторяющиеся занятия через 1–4 недели, перенос и удаление. Для схемы A/B создайте отдельные события с нужными шаблонами; для двухнедельного цикла задайте повтор через 2 недели. Напоминания включаются отдельно для каждого события.
11. **Более точная аналитика:** точки по тренировкам, фильтр разминки и сравнение равных прошедших частей периодов.
12. **Следующий план:** кнопка в шаблоне предлагает прибавить заданный пользователем шаг веса, только если все рабочие подходы последнего выполнения достигли верхней границы повторов и заданного веса. Число подходов должно быть не меньше плана. Повторы возвращаются к нижней границе. Индивидуальные планы подходов не изменяются. Предложение содержит объяснение и сохраняется только по кнопке «Применить к шаблону».

## Индивидуальные подходы в CSV

В `set_plan` передаётся массив объектов с полями `reps`, `weight`, `durationSeconds`, `distance`, `warmup`. Для силовых нужны вес и повторы, для кардио — длительность и дистанция, для упражнения на время — длительность. `warmup=true` обозначает разминку. Общий `sets` — число рабочих подходов, если индивидуальный план пуст; при наличии массива число рабочих подходов определяется элементами с `warmup=false`.

Пример JSON до экранирования для CSV:

```json
[{"reps":10,"weight":20,"warmup":true},{"reps":8,"weight":70,"warmup":false}]
```

В CSV поле заключается в кавычки, а внутренние кавычки удваиваются. Готовый файл с правильным экранированием — [workout-per-set-example.csv](docs/workout-per-set-example.csv).

## CSV истории: импорт и экспорт

Этот формат записывает **фактические подходы прошедших тренировок**, не будущий план. Пример: [docs/history-example.csv](docs/history-example.csv). Экспорт в разделе истории выгружает выбранный месяц по часовому поясу пользователя.

```csv
session,workout,started_at,finished_at,exercise_position,exercise,metric_type,weight,reps,duration_seconds,distance,rpe,notes,warmup,paused_seconds
old-1,Грудь,2026-01-10T15:00:00Z,2026-01-10T16:00:00Z,0,Bench Press,STRENGTH,20,10,,,,Разминка,true,120
old-1,Грудь,2026-01-10T15:00:00Z,2026-01-10T16:00:00Z,0,Bench Press,STRENGTH,70,8,,,8,Хорошая техника,false,120
```

- `session` — произвольный идентификатор группировки строк в файле; это не ID для изменения существующей тренировки.
- `workout`, `started_at`, `finished_at`, `paused_seconds` должны совпадать у всех строк одной тренировки. Время — ISO 8601 с часовым поясом (`Z` или смещение), окончание позже начала и не в будущем. Паузы — целые секунды от нуля до длительности занятия.
- `exercise_position` — позиция 0–29. Одинаковая позиция внутри тренировки означает одно упражнение с одинаковыми названием и типом. Строки одного упражнения — подходы в порядке файла.
- Метрики соответствуют типу упражнения; `rpe` и `notes` необязательны. `warmup` — строго `true` или `false`.
- Остальные правила UTF-8, кавычек, разделителей и размера 64 КиБ совпадают с импортом шаблонов. До 100 тренировок за файл, до 30 упражнений и 100 подходов на упражнение. Большой месячный экспорт можно разбить на файлы, сохраняя все строки каждой тренировки вместе и повторяя заголовок.
- Предпросмотр не меняет базу. Сохранение всего файла атомарно. Повторный импорт идентичного файла тем же пользователем возвращает ошибку; изменённый файл считается новым импортом. Экспорт содержит реальные подходы, заметки, признак разминки и длительность пауз; шаблоны, их цели и расписание в него не входят. CSV не заменяет резервную копию PostgreSQL.
- Ручное добавление и импорт не затрагивают текущую активную тренировку. Они сразу обновляют историю, статистику и рекорды.

## Интерфейс и графики

В главном меню одно основное действие: «Начать тренировку» или «Продолжить тренировку», если она уже идёт. Разделы расположены по две кнопки в строке. Синим выделяются основные действия и выбранный период, зелёным — сохранение/завершение, красным — подтверждение удаления или отмены. Подписи и подтверждения остаются понятными и без цветового оформления.

В редакторе шаблона нажмите на упражнение, чтобы изменить план, переместить его выше/ниже или убрать. Стрелки перелистывания находятся рядом; на вложенных экранах есть «Назад» и «Меню».

**Прогресс** сразу открывает график текущего месяца в виде изображения в Telegram. Кнопками можно выбрать неделю, месяц, три месяца или год. На двух отдельных шкалах показаны силовой объём в кг и число тренировок по дням. Дни отдыха имеют нулевые значения, будущие дни не отображаются. «По дням» открывает точные значения списком.

**Прогресс → Упражнения → упражнение** показывает лучший результат каждой завершённой тренировки отдельной точкой, даже если несколько тренировок прошли в одном месяце или дне. Расстояние между точками соответствует порядку тренировок. Одна запись отображается точкой. При отсутствии данных бот предлагает завершить тренировку вместо выдуманного графика.

Графики учитывают только завершённые тренировки и часовой пояс пользователя. Подписи соответствуют выбранному языку. Изображения строятся локально в Java; сторонние сервисы графиков не получают данные. PNG передаётся непосредственно Telegram. При переключении периодов изображение редактируется; при возвращении к текстовому экрану бот создаёт текстовое сообщение и пытается удалить прежний график. Если Telegram не позволяет удалить его, старое изображение может остаться в чате; его кнопки уже не изменяют состояние.

## История, прогресс и рекорды

История разбита по месяцам и страницам. У каждой тренировки есть итог и подробный список упражнений/подходов. История упражнения показывает последние результаты со ссылками на полные тренировки.

Периоды отчётов: эта неделя, этот месяц, последние три календарных месяца (включая текущий), этот год. Доступны число тренировок, выполненных упражнений, подходов, повторов, длительность, силовой объём и частота по дням.

По умолчанию сравниваются **равные прошедшие части периодов** с точностью до текущего местного времени. Например, 10 сентября в 12:00 сравнение идёт с 1–10 августа до 12:00. Если предыдущий период короче, обе части ограничиваются его длиной; конечная дата отчёта отражает это ограничение. Через API можно запросить прежнее сравнение с полным периодом (`equalElapsed=false`). При нулевой базе процент изменения не выводится. Средняя частота рассчитывается по уже прошедшим календарным дням. Принадлежность тренировки периоду определяется временем начала. Учитываются только завершённые тренировки; упражнение считается выполненным, если есть хотя бы один неотменённый подход.

Силовой объём — сумма `вес × повторы` только для силовых упражнений. Собственный вес, кардио и упражнения на время его не увеличивают. Длительность — время между началом и завершением за вычетом сохранённых пауз. Отдых между подходами входит во время тренировки.

В прогрессе по умолчанию учитываются рабочие подходы; кнопка переключает выборку на все, включая разминку. Итоги конкретной тренировки показывают все её подходы. Силовые рекорды всегда исключают разминку. После завершения обновляются рекорды: максимальный вес, максимум повторов, лучший объём подхода и тренировки, расчётный одноповторный максимум (1ПМ) по Эпли. Для одного повтора используется фактический вес; для нуля повторов оценка отсутствует. При большом числе повторов оценка менее точна.

Показатели прогресса: 1ПМ для силовых, повторы для собственного веса, расстояние для кардио, длительность для упражнений на время. В API `bySession=false` сохраняет группировку по месячным максимумам. Исправление или удаление подхода завершённой тренировки пересчитывает рекорды заново, включая уменьшение ошибочных значений.

OpenAPI и health открыты на локальном HTTP-порту. Запросы `/api/*` требуют заголовков:

```text
X-Api-Key: <INTERNAL_API_KEY>
X-Telegram-User-Id: <положительный Telegram ID пользователя>
```

Ключ предназначен для **доверенного внутреннего сервиса, который может действовать от имени пользователей**. Это не пользовательская авторизация. Не помещайте ключ в браузерное/мобильное приложение и не публикуйте сервис напрямую в интернете. Для публичного клиента нужен шлюз с проверкой личности Telegram. При пустом ключе внутренний API возвращает 503.

В Swagger укажите оба заголовка через Authorize. `POST /api/me` позволяет зарегистрировать пользователя для разработки и внутренних запросов без обращения к Telegram.

Размер страницы: 8 элементов для шаблонов, каталога и истории; 5 тренировок для истории упражнения. Начало, повтор тренировки и запись подхода требуют `Idempotency-Key` длиной 1–100 символов. Повторяйте ключ при сетевой повторной попытке; используйте новый для нового действия. Другие данные с прежним ключом дают 409. Завершение, отмена и отмена подхода идемпотентны. Создание шаблонов, CSV-импорт и создание упражнений не используют ключ идемпотентности.

Пример тела шаблона (ID упражнений получите через `/api/exercises?q=Bench`):

```json
{
  "name": "Грудь и плечи",
  "description": "Силовая тренировка",
  "exercises": [
    {"exerciseId": 1, "sets": 3, "reps": 8, "weight": 70, "restSeconds": 90},
    {"exerciseId": 16, "sets": 3, "reps": 10, "weight": 20, "restSeconds": 60}
  ]
}
```

Начало: `{"templateId":1}`. Подход: `{"sessionExerciseId":1,"weight":70,"repetitions":8}`. Здесь нужен **ID упражнения в начатой сессии**, а не ID из каталога.

Настройки: `PATCH /api/me` с `{"timezone":"Europe/Moscow","language":"ru"}`. Оба поля необязательны; пропущенное или `null` не меняет соответствующую настройку. Поддерживаются только `ru` и `en`. Ошибки API — Problem Detail без трассировок стека.

Пример импорта через PowerShell с переменными окружения, заданными в текущей оболочке:

```powershell
curl.exe -X POST http://localhost:8080/api/workouts/import `
  -H "X-Api-Key: $env:INTERNAL_API_KEY" `
  -H "X-Telegram-User-Id: $env:TELEGRAM_USER_ID" `
  -F "file=@docs/workout-example.csv;type=text/csv"
```

`TELEGRAM_USER_ID` в примере — ID заранее зарегистрированного пользователя. PowerShell сам не загружает `.env`. Импорт через API сохраняет шаблон сразу, без Telegram-экрана подтверждения.

## Архитектура и надёжность

Приложение — модульный монолит. Telegram и REST вызывают общие транзакционные сервисы; расчёты и запись данных не зависят от транспорта.

```text
telegram/{bot,callback,handler,message}  Telegram, сохранённое состояние интерфейса, экраны
workout/{domain,application,api}         Шаблоны, CSV, тренировки, подходы
exercise/{domain,application,api}        Общий каталог и личные упражнения
analytics/{domain,application,api}       Отчёты и рекорды
user/{domain,application,api}            Профиль, язык и часовой пояс
common/{api}                           Проверки, переводы, ошибки, авторизация, OpenAPI
```

Spring Data хранит агрегаты; JPA выполняет транзакционные изменения, аналитика использует параметризованные SQL-запросы. Часы `Clock` внедряются зависимостью. DTO API отделены от JPA-сущностей. Переводы находятся в `src/main/resources/i18n/ru.json`: переводятся только явно отмеченные строки приложения, пользовательский текст не изменяется. Языковой контекст ограничен обработкой одного Telegram-обновления и восстанавливается в `finally`.

- Блокировка пользователя в БД последовательно выполняет его изменения из Telegram и REST. Частичный уникальный индекс запрещает две активные тренировки.
- Сессия сохраняет снимок порядка, названий, типов и плана упражнений. Удаление шаблона мягкое; завершённую тренировку можно повторить после удаления шаблона.
- Ключи запросов защищают начало, повтор и запись подходов от повторного выполнения. Отмена подхода помечает его недействительным, сохраняя ключ.
- Кнопки содержат ревизию экрана. Устаревшая кнопка или кнопка другого сообщения не изменяет состояние.
- Изменения данных, следующий polling offset, состояние ввода и экран фиксируются одной транзакцией. Ошибки БД оставляют обновление для повторной обработки.
- Очередь исходящих экранов в PostgreSQL повторяет доставку без повторного выполнения действий. Удалённое сообщение заменяется новым. Ограничение частоты учитывает `retry_after`; URL с токеном не включается в транспортные исключения.
- CSV и скачивание ограничены 64 КиБ. Telegram-файлы загружаются через `getFile` с ограничением времени и размера; токен не выводится в ошибки.
- Hibernate только проверяет схему (`ddl-auto=validate`), изменения выполняет Flyway.

## Разработка и тестирование

Установите JDK 17+ и запустите Docker. Maven Wrapper автоматически загружает Maven 3.9.11.

```powershell
.\mvnw.cmd test             # Модульные тесты и HTTP-адаптер Telegram
.\mvnw.cmd verify           # Также PostgreSQL Testcontainers и проверка форматирования
.\mvnw.cmd spotless:apply   # Форматирование Java
```

В Linux/macOS замените `.\mvnw.cmd` на `./mvnw`. Интеграционные тесты требуют Docker и завершаются ошибкой, если он недоступен. Они используют временные базы, не рабочий том Compose. CI выполняет `verify` на Ubuntu.

Для запущенного Compose:

```powershell
powershell -File scripts/smoke-test.ps1 -Restart
```

Скрипт проверяет полный цикл REST-тренировки и сохранность данных после перезапуска. Он создаёт и оставляет данные под новым синтетическим ID, не обращаясь к реальному аккаунту Telegram. Без `-Restart` приложение не перезапускается.

Тесты проверяют тренировку из трёх подходов 70×8 и подходов 20×10, 20×10, 20×8 (объём 2240 кг), предыдущие результаты, устаревшие кнопки, конкурирующие запросы, отмену, принадлежность данных пользователю, типы показателей, периоды и часовые пояса, рекорды, снимки, миграции, API и восстановление контекста. Дополнительно проверяются выбор и изоляция языка, CSV с кириллицей/кавычками/BOM, ограничения, откат импорта, приватность упражнений, импорт через REST и Telegram-черновик. HTTP-адаптер Telegram использует локальный поддельный сервер. Проверяются отправка и редактирование PNG, возврат к текстовому меню, ограничения Telegram, чтение старых сохранённых экранов, пропуски данных на графике и новая навигация.

Для запуска Java без контейнера задайте в окружении процесса `SPRING_DATASOURCE_URL`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `INTERNAL_API_KEY` и при необходимости переменные Telegram, затем выполните `.\mvnw.cmd spring-boot:run`. Spring **не загружает `.env` автоматически**, в отличие от Compose. Базу для разработки можно запустить так:

```sh
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d db
```

URL локального подключения: `jdbc:postgresql://localhost:5433/workout`.

Структурированные ECS JSON-логи выводятся в stdout. Actuator предоставляет health и Prometheus; счётчики `workout.telegram.updates` и `workout.telegram.errors` отражают работу транспорта. Не включайте логирование полных HTTP-запросов с рабочим токеном.

## Ограничения

- Один polling-процесс на бота/базу; webhook и несколько реплик не поддерживаются. Перед запуском отключите существующий webhook. Ошибка Telegram 409 обычно означает другой потребитель обновлений или активный webhook.
- Для Telegram нужны токен и исходящее HTTPS-соединение. Автотесты не проверяют доставку в реальный аккаунт.
- Нет подсчёта калорий, питания, ИИ-тренера, социальных функций, платежей, носимых устройств.
- Таймер отображает остаток на момент обновления экрана; кнопка «Обновить таймер» обновляет значение. Уведомления опциональны. После простоя свыше двух минут устаревший сигнал отдыха не отправляется; напоминания о занятиях старше суток также пропускаются.
- Готовых программ нет: шаблоны создаются вручную или импортируются; упражнения общего каталога предзаполнены.
- До 30 упражнений в шаблоне, 100 действующих подходов на упражнение, 80 символов в названиях и 500 в заметках/описаниях. Длинные списки разбиваются на страницы.
- Между успешным `sendMessage` и сохранением ID возможен сбой: при восстановлении изредка создаётся второе сообщение интерфейса. Подтверждённые подходы не дублируются.
- Профиль создаётся при первом обращении; приветствие считается пройденным после кнопки «Начать».

Первоисточники: [Telegram Bot API](https://core.telegram.org/bots/api), [требования Spring Boot 3.5](https://docs.spring.io/spring-boot/3.5/system-requirements.html).
